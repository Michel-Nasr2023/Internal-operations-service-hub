# ADR-001: Use a Relational Database as the Workflow System of Record

## 1. Problem

The Internal Operations Service Hub must track requests from creation to resolution. It needs reliable relationships between tickets, users, teams, assignments, approvals, comments, attachments, notifications, and audit events.

The system must also enforce valid state transitions, prevent duplicate assignments or submissions, support authorization checks, and provide accurate queues and dashboards. The chosen storage approach must preserve an audit trail and support recovery when notifications or background jobs fail.

## 2. Options

### Option A: Relational database

Store workflow entities in normalized tables connected by foreign keys and enforce business constraints with transactions, unique constraints, and optimistic concurrency.

### Option B: Document database

Store each ticket and much of its workflow history as a document, embedding assignments, comments, approvals, and other related data.

### Option C: Multiple specialized stores as the primary source

Split tickets, workflow state, audit events, and operational data across different primary systems, synchronizing them through events.

## 3. Decision

Use a **relational database as the authoritative system of record** for workflow data.

Store ticket state, users and team references, assignments, approvals, comments, attachment metadata, notifications, and audit events in relational tables. Use database transactions for state changes and enforce important invariants, such as one active assignment per ticket and unique idempotency keys.

Store attachment bytes separately in secure object storage; keep only metadata and an opaque object key in the relational database.

## 4. Consequences

### Benefits

- Relationships and cardinality are explicit and enforceable.
- State transitions, assignments, approvals, and audit events can be updated atomically.
- Queries for queues, dashboards, overdue work, and authorization are straightforward.
- Unique constraints and transactions reduce duplicate or invalid workflow records.
- Relational backups provide a clear recovery source for durable business data.
- Object storage avoids placing large file contents in ticket rows.
